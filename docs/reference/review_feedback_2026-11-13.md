심사 및 분야
공식 안내의 네 주제는 예시이며 별도 지원 분야 구분은 없습니다. 현재안은 ‘모빌리티 & 라이프 편의’로 설명하기 자연스럽지만, 특정 분야가 심사상 유리하다는 근거는 없어요. 공개된 네 심사 항목은 1차 서류 기준이고 상세 PT 기준은 추후 안내입니다. 첫 타깃은 ‘주말 나들이를 자주 하지만 따로 일기는 쓰지 않는 운전자’처럼 좁혀 검증해 보면 좋겠습니다. 공식 개요 · 심사 기준

UC별 빠른 평가
아래는 기획상 상대평가이며 공식 점수나 입상 확률이 아닙니다. 사업성은 사용자 검증 전이라 보수적으로 봤습니다. 하위권이라도 안전·개인정보 기능은 필수입니다.
핵심 후보: UC-01 자동 기록, 03 차량 단서, 07b 도착 후 회고, 11 다시 보기, 12 회상 질문. 01의 오판과 03의 잘못된 해석을 해결하는 것이 전제입니다.
조건부: 02 동승자 맥락은 신원 자동 확정 금지, 06 음성 메모는 호출·오디오 포커스·주행 중 허용 경로 확인, 04 음악은 타 앱 정보 접근 미확인, 13 자동 알림은 주의 분산 위험이 있습니다.
보조·후순위: 08 누락 보완, 14 누적 기록, 15 검색, 17 공유는 가치가 있지만 대표 데모의 차별점을 먼저 보여주는 편이 좋아요.
우선순위를 올릴 필수 기능: 09 주행 제한, 10 오판·오류 복구, 18 개인정보 제어. 삭제된 05·07·16은 제외했습니다.


수정하면 좋을 핵심
UC-01+10: 완전 자동 확정보다는 ‘자동 초안 + 사용자 보정’. 신호 대기·동승자 하차·짧은 경유에서 임시 종료, 재개, 병합을 시험하세요. 트립 종료 추정은 안전한 주차 판정이 아닙니다.
UC-03+12+07b: 관측 사실 → 기억 단서 제안 → 사용자 확인 → 저장. ‘와이퍼 작동=비’, ‘전조등=야간’처럼 단정하지 말고 실제 신호와 사용자의 해석을 구분하세요.
안전·프라이버시를 P1으로: 회고 시작과 타임라인 감상에도 플랫폼 UX 제한을 적용하고, 상태를 확인할 수 없다면 제한 기능을 열지 않는 방향을 권합니다. 수집 선택·일시정지·동승자 동의·삭제도 첫 데모에서 보여주세요. 주행 제한 가이드
지도·음성 의존성 분리: FusedLocation은 위치 API이지 지도 배경이나 장소명을 보장하지 않습니다. 외부 API 없이 지도 표시가 가능한지 확인이 필요해요. STT/TTS의 기본 HYBRID 모드는 서버를 사용할 수 있으므로 ‘외부 API 직접 미사용’과 ‘완전 온디바이스’는 다릅니다. 위치 API · STT
