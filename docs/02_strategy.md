# 02. 입상 전략

팀 분석 결과(2026-10-30 ~ 11-13). 공식 심사 기준이 아니라 우리의 해석임.

## 한 줄 전략

> **핵심 흐름은 실제 Vehicle SDK로 동작시키고, 준비 중 SDK 기능은 SIL(Software-in-the-Loop) 방식의 시나리오 재생으로 검증한다.**
> 그리고 "차가 이동 중 기억의 단서를 모으고, 주차 후 사용자가 의미를 붙인다"는 **한 장면**에 집중한다.

## 제품 정의

- 이름(가제): Pleos Journal
- 대상: 대부분의 운전자. 첫 검증 타깃은 "주말 나들이를 자주 하지만 따로 일기는 쓰지 않는 운전자"로 좁힌다.
- 목적: 차량을 이용한 여행과 일상 이동 경험을 iPhone Journal 앱처럼 쉽게 기록.
- 대표 시나리오: 가족과 서울에서 제천 당일치기(제비봉 등산, 도담삼봉, 식사). 귀갓길에 가족은 뒷좌석에서 잠들고 운전자는 잔잔한 음악을 들으며 운전. 귀가 후(또는 며칠 뒤) 음성으로 그날을 이야기하면, 앱이 그 시간의 차량 단서(휴식 구간, 창문, 와이퍼 등), 경로, 음악과 묶어 기록으로 남김.

## 가장 큰 위험: "차량 신호가 붙은 일기장"

- 음성으로 말하면 경로, 음악을 붙여주는 기능은 폰 앱도 한다.
- 차별점은 **차만 아는 단서**(뒷좌석 등받이 젖힘, 좌석별 착석, 창문, 와이퍼, 전조등, 실내 공조)가 회상을 돕는다는 점이다.
- 순간을 3층으로 나눠 기획서에 배치한다.

| 층 | 예시 | 기획서 역할 |
|---|---|---|
| 차량 전용 | 휴식 구간, 동승자, 와이퍼 구간, 창문 열고 달린 구간 | 헤드라인 (차별점) |
| 공통 | 음성 회고, 경로, 음악 | 당연히 되는 기본 기능 |
| 폰 전용 | 사진, 하차 후 걷기 | 로드맵 (Pleos 폰 연동 확인 시) |

## 심사 항목별 대응

| 항목 | 우리의 답 | 증거로 보여줄 것 |
|---|---|---|
| 차량특화성 | 차량 신호가 "기억의 단서"가 된다. 폰은 뒷좌석이 잠들었는지 모른다 | 단서 제안 화면, 단서 규칙표 |
| 창의성 | 기록 앱의 핵심 난제(쓰기 귀찮음, 무엇을 쓸지 모름)를 "차가 질문을 건넨다"로 해결 | 단서 기반 질문 vs 일반 질문 비교 |
| 기술 활용성 | Vehicle SDK 다수 도메인(Seat, Door, Window, Wiper, Light, HVAC, Odometer, EvBattery/Fuel) + STT/TTS/FusedLocation 인터페이스 설계 + UX 제한 대응 | 실동작/SIL 구분표, 출처 배지가 보이는 화면 |
| 사업성 | 아래 "사업성 가설" 참고. **가장 약한 칸이므로 직접 보강 필요** | 가설과 검증 계획 |

## 실동작 vs SIL 구분 (기획서와 화면 모두에 표기)

| 구분 | 기능 | 근거 |
|---|---|---|
| 실제 SDK 입력 | 착석, 벨트, 도어, 창문, 와이퍼, 전조등, 등받이 각도, 실내온도, 트립 거리/시간, 배터리/연료 | Vehicle SDK 사용 가능 |
| SIL 재생 입력 | 위치(FusedLocation), 음성 입력(STT), 음성 안내(TTS) | 준비 중 SDK. 공식 문서 인터페이스 기준으로 구현, 시나리오 신호로 검증 |
| 앱 내부 처리 | 트립 판정, 단서 추출, 장면 제안, 저장, 타임라인 | 앱 로직 |

- SIL 서사: "제어/음성 SDK 인터페이스는 공식 문서 기준으로 구현했고, 개방 전까지는 시나리오 신호로 검증했다. 개방되면 소스만 교체한다." 양산 SW 경험자다운 신뢰감, 박민우 사장의 "실행력" 키워드와 연결.

## 안전 설계 (팀 전문성: ISO 26262, SOTIF)

- 관측 사실과 해석 분리: 단서는 단정하지 않고 사용자 확인을 받는다. 오인식 가능성을 전제로 한 설계(SOTIF 관점).
- 주행 중 화면 입력 없음. 입력 UI는 플랫폼 UX 제한이 풀렸을 때만 열고, 상태를 모르면 닫는다(fail-safe).
- 트립 종료 추정은 안전 판단에 쓰지 않는다.
- 오판 복구: 트립 병합, 분할, 단서 삭제, 수정.
- 프라이버시: 항목별 수집 선택, 일시정지, 동승자 동의, 삭제, 로컬 저장.

## 비전 연결 (기획서 서사용, 과장 금지)

- 박민우 사장 키워드: 실행(Execution), 데이터 플라이휠, 피지컬 AI와 신뢰, 서비스로서의 자율주행.
- 연결 포인트:
  - 실행: 지금 양산 차량에서 쓸 수 있는 신호만으로 동작.
  - 개인 단위 데이터 플라이휠: 기록이 쌓일수록 회상(1년 전 이 길, 명절 귀성 비교)의 가치가 커짐.
  - 자율주행 시대: 운전에서 해방된 탑승 시간이 늘수록 "차 안의 경험을 남기는" 수요가 커진다는 미래 서사(비전 섹션에만).
- 비전은 가산 렌즈일 뿐 채점표가 아니다.

## 사업성 가설 (미검증, 직접 보강 필요)

- OEM 기본 앱 또는 번들: 차와의 추억이 쌓이면 브랜드 애착과 재구매로 연결(차량 매각 시 "이 차와의 이야기" 리캡).
- 프리미엄 기능: 기간 리캡 내보내기, 공유 카드 디자인.
- 차량 데이터 활용 서비스의 사용자 동의 기반 확장 가능성.
- 검증 계획: PT 전 지인 몇 명 대상 "일반 회고 질문 vs 차량 단서 제안" 비교. 기록 완성률과 떠올린 기억의 구체성 관찰.

## 경쟁, 유사 서비스 (참고)

- 폰 기반: iPhone Journal, Google 타임라인.
- 차량 내 공간 모드류(초기 아이디어 단계에서 조사): Tesla Camp Mode, Rivian Camp Mode, 현대차 유틸리티 모드, Mercedes ENERGIZING COMFORT, EQS Power Nap, Genesis Mood Curator. 이 계열은 경쟁이 많아 방향 전환함.
- 차량 기록 저널 형태의 직접 경쟁 제품은 아직 조사하지 않음(확인 필요: Pleos App Market 유사 앱).

## PT 예상 질문과 대응

| 질문 | 대응 |
|---|---|
| 휴대전화 일기와 무엇이 다른가? | 차만 아는 단서가 질문을 만든다. 비교 관찰 결과 제시 |

| 동승자 정보 노출, 공용 차량은? | 동승자 동의, 수집 중지, 로컬 저장, 삭제 |
| 시동/속도 신호도 없는데 트립을 어떻게 아나? | 조합 판정 + 사용자 보정. 판정 로직과 실패 처리 설명 |
